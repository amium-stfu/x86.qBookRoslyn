## Objective and Resolved Decisions

The user reports an unreachable `BoxModule` value area, including a missing hand cursor, for this application usage:

```csharp
Add(total_iBox = new BoxModule("total_i", target: test.I_Total,
    backColor: "Transparent", locked: false),
    column: 1, row: 1, columnSpan: 4, rowSpan: 3, boxTable: SignalView);
```

The reference application file is `B:\Audi\CellTester_2026.08.26.code\Pages\TestSystem\TestSystem.cell_test_view.cs`. It is read-only evidence and is not an implementation target.

`QB.Item.Directory` is initially inferred from a `Definition...` namespace in the creation call stack. `Frame.Directory = Page` does not propagate to child controls. Rendering traverses frame children, while the central interaction lookup filters each registered control by its own `Directory`. Consequently, an inner control may render while being excluded from the owning page's interaction candidates. The current `BoxModule` explicitly assigns only the frame's directory; its `Read`, `Set` and `Out` children have callbacks but no explicit page assignment.

The confirmed solution is to close this and equivalent page-assignment gaps in composed controls within `BoxView.cs`. The control's configured `Page` at creation is authoritative for its frame and nested controls. Assign it explicitly instead of relying on the calling namespace. This is a local creation-time correction, not a global change to `Item.Directory`, automatic page migration or a redesign of hit testing.

For `BoxModule`, `locked: true` must disable all three existing interaction areas: `Read`, `Set` and `Out`, immediately after creation and after repeated hide/show cycles. For a visible unlocked module, preserve the existing callbacks: `Read` edits `Target.Set`, `Set` edits `Target.Set` with its existing Min/Max arguments, and `Out` edits `Target.Out`. Do not change these target semantics or enlarge their click surfaces.
