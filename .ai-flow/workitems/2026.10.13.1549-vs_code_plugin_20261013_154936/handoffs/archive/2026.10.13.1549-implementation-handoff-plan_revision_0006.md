## Current evidence and resulting design

- BookRuntime.StopAll currently wraps ReleaseResources in the implemented BeginBookTeardown/EndBookTeardown boundary, but retains assembly bindings. DestroyAll additionally clears those bindings and unloads the assembly.
- RunAll currently supports reinitialization after resource-only Stop; this special restart behavior is no longer required.
- The extension saves and backs up before sending Rebuild, then sets pendingAutoRunAfterRebuild. A rebuild status signal currently causes the extension to send Run.
- PipeCommands.Rebuild calls Core.OpenQbookAsync followed by Core.Initialize. OpenQbookAsync already destroys the previous book before rebuilding, but catches exceptions and returns no success result. BuildAssembly also calls DestroyAll. Cleanup must be idempotent so these existing nested entry points do not repeat user Destroy hooks for already released resources.

Use host-owned sequential execution for the runtime stages of Rebuild. The extension owns save and backup; after those succeed it sends one Rebuild command. The host owns Destroy/Build/Initialize/Run and calls Run exactly once after successful initialization. Remove the extension's pending-auto-Run mechanism to prevent duplicate runs or stale heartbeat-triggered runs. Keep the internal Run command for host/runtime compatibility; removing the button does not remove that command.
