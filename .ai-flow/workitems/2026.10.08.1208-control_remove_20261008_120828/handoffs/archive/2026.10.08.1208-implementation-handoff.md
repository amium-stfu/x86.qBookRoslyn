## Goal and Public Interface

New public parameterless instance method `public void BoxTable.RemoveControl()` in `qbookCsScript/Controls/BoxView.cs`:

1. Idempotent: a second call after successful removal has no further effect (same pattern as the existing `UIBox.RemoveControl()`).
2. Invokes the owner back-reference `DetachFromOwner` once (if set) and then nulls it, removing the `BoxTable` instance from the `BoxView` list it was added to via `BoxView.Add(object box)`.
3. Iterates a snapshot of `Boxes.Values` (the child `UIBox` dictionary) and calls `RemoveControl()` on each entry, then clears `Boxes`.
4. Removes the container's own `Frame` control tree via `Frame?.Remove();` and nulls `Frame`.
5. Is inherited automatically (no override needed) by `BoxFlowPanel`, `BoxDialogWithParameters`, `BoxLogView`, `BoxProcessLogView` — all derive from `BoxTable`.

Additionally, `BoxView.Add(object box)` wires the new owner back-reference for the four `BoxTable`-derived branches, and `BoxTable.Add(UIBox box, ...)` / `BoxFlowPanel.Add(...)` wire the existing `UIBox.DetachFromOwner` for directly-added child boxes (closing a gap that already existed for the `boxTable`/`boxFlowPanel` direct-add path, independent of `BoxView.Add(UIBox, boxTable: ...)`).

   - A private idempotency flag: `private bool removed;`.
   - The new public method:
     ```csharp
     /// <summary>
     /// Removes the complete control tree of this container and all currently contained child boxes,
     /// and detaches it from its owner collection if it was added via <see cref="BoxView.Add(object)"/>.
     /// Calling this method more than once has no effect.
     /// </summary>
     public void RemoveControl()
     {
         if (removed) return;
         removed = true;

         DetachFromOwner?.Invoke();
         DetachFromOwner = null;

         foreach (UIBox box in Boxes.Values.ToList())
         {
             box.RemoveControl();
         }
         Boxes.Clear();

         Frame?.Remove();
         Frame = null;
     }
     ```
