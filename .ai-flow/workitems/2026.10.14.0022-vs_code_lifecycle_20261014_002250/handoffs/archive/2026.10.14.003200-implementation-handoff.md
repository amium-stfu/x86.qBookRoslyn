## Problem and required outcome

Initial application/book startup works, but rebuilding an already started book reports `Collection was modified; enumeration operation may not execute`, followed by `Book cleanup, loading or build failed`. Another reported failure reaches `QB.Program.Run()` and throws `ArgumentNullException` for `path1` in the external book's `FunkyTest` constructor. Stop/Rebuild also clear the host-rendered header/footer.

Investigate these lifecycle regressions and correct their causes within the write scope below. Preserve the host frame, header/footer, navigation, status, and valid book context while destroying and replacing the book runtime. Do not claim that the two exceptions have one cause without evidence.

### Resolved behavior

1. Stop destroys book runtime resources, removes runtime UI, clears dynamic page/program bindings, and requests unloading of the runtime assembly. It keeps the host application, frame, header/footer, navigation, status, and loaded book context available.
2. Rebuild performs Save -> Backup -> Destroy -> Build -> Initialize -> one global Run. The existing extension owns Save and Backup; the host owns runtime teardown, loading/building, initialization, and Run. No additional client-side Run is sent.
3. A failed stage prevents subsequent stages. Save/Backup failure leaves the existing runtime intact. Cleanup/loading/build/initialization failure must not lead to Run. Run failure must not be reported as success.
4. Repeated Rebuild after Start and Stop -> Rebuild must work. Destroy must safely handle an already stopped/unbound runtime without invoking the prior runtime's cleanup repeatedly or losing the host context.
5. The book binding used by `QB.Book` and runtime code must refer to the appropriate valid book during initialization and Run. Preserve configured data/settings/temp directory semantics and existing valid defaults; do not substitute arbitrary paths to hide null errors.
6. Host drawing must continue without executing torn-down or partially initialized book runtime code. Runtime teardown is allowed to clear book-owned content; it must not blank the whole `PageControl` including its host frame.
7. Preserve existing Check Code, standalone Backup, Debug, toolbar layout, command identities, and the absence of a separate Run button. Preserve the existing source reload behavior so Rebuild consumes saved source changes.
